# Draft: causal LR-only interpretation revision and long return

No new data, DiT or training run is started by this draft. B5 remains its frozen hard-band2×2 diagnostic. This is a proposed next protocol, to be frozen separately after B5's information-path results.

## Question and outputs

At prefixA, the system has an actual LR observation whose interpretation remains ambiguous. It must retain the corresponding detail/geometry relationship. At prefixAB, a later independent LR cue resolves that interpretation. The system may revise details correlated with the cue, including current-near-null high frequencies, while preserving unrelated detail from its own actual H3 prior. Later far queries test whether the newly acquired detail survives a long absence. The primary output is the current frame at a declared bounded wait; a stored canonical-view requery is a separate memory diagnostic and must not be reported as a zero-latency current-frame output.

Separate three claims: transmitting observed detail, correctly revising the interpretation of that evidence, and using a generative prior beyond the directly observed band. A positive classical bridge only demonstrates the first. Early→late posterior concentration alone does not establish a joint-memory test; nonseparable early associations and actual pre-cue compression must be audited.

## Data/provenance and timing

Use two named tiers. Controlled natural-photo camera episodes provide known evaluation geometry and a static canonical GT; they remain simulation, not real motion. Existing real DAVIS/long-stream footage provides nonrigid motion, occlusion and model mismatch; infer correspondence, identity and photometry from LR only. Simulator camera/scene/group/change labels and HR masks may supervise/train or define evaluation regions, never enter normal inference. The existing B simulator's capture-group tags must be explicitly removed or retained only as an oracle-control arm; it is not an LR-only discovery result.

Do not touch sealed DIV2K. All BSDS and existing eight real-video sources are development data already used in this project; any new protocol on them is not a fresh confirmation. Train/val are source-disjoint and fixed before another model comparison. Future confirmation needs genuinely new motion sources after freezing the mechanism, not unused crops of a previously evaluated source.

A concrete controlled schedule can use600physical frames at24fps: initial far0–21; first nearA22–27; away/occluded28–179; independent overlapping/anchored nearB180–185; further absence186–575; far/near return576–599. This is25s, not minutes or arbitrarily long memory. Also report absence lengths32/128/512 with the same architecture, without selecting a favorable length. Native22 context is distinct from physical packet count; repeating an already observed image fills codec context without manufacturing22measurements. Exact repeated IDs are no-ops, whereas independently noisy repeat captures add coarse information.

The proposed controlled far scale8 versus old scale4 must be a new declared protocol, not a retrofit chosen to improve a result. More severe initial downsampling can leave natural ambiguity; it does not by itself prove that H3 supplies useful diverse explanations. Near scale and camera path are fixed from TRAIN design, not val entropy/PSNR. Keep the physical noise/quantization model and likelihood scale fixed and audit residual model mismatch instead of raising likelihood temperature to create uncertainty.

## Required prefix identifiability audit

1. Store every prefix payload with physical arrival times and observation IDs. Construct stateA in a process that receives only packets≤A, save it, and independently reproduce that prefix with poisoned future LR/codes. State/first readouts must be unchanged. Compression/write occurs here, **beforeB**. GT files are separate evaluation/loss inputs.
2. Infer correspondence/operator alternatives from LR evidence. Natural repeated textures/subpixel matches are useful candidates, but selection rules must be trained/frozen on TRAIN; do not choose only val examples where the new method wins. Retain/reweight unresolved alternatives instead of giving the model simulator geometry or the correct object/group identity.
3. With an explicitly declared finite far-only H3 prior/control, report prior→A→AB joint weights, conditional geometry distributions, carrier marginals, early conditional entropy, mutual information and actual decoded alternative errors. The useful case has early content/operator association and a late cue that changes the required detail; both a mere uncertain independent marginal and final onehot alone are insufficient. Candidate response grids already conditioned on a scored cue must not be called exact Bayes posteriors. Exact finite MHT is exact only for its specified prior/likelihood.
4. If actual H3 explanations remain nearly identical, state it. Do not manufacture identity modes via hand-coded offsets, oracle labels or arbitrary noise and attribute them to natural H3 ability. A mathematical opposite-correlation example is only an interface check. A failed identifiability audit diagnoses the protocol; it does not justify claiming a memory mechanism was disproved.

## Shared observation carrier and learned correction

All learned/strong controls share the same retained original LR packets or authoritative full24 native observations, IDs and causal controller, with full memory/call accounting. Keep a quality-preserving observed-data bridge as a baseline, and initialize a learned residual to0. This removes the previous confound of losing observed detail in a randomly learned bottleneck. If the method claims compression, original LR/proxy/full-code retention must be counted; it cannot keep the archive for free.

A candidate side state represents **operator-conditioned correction responses**, written from prefixA and queried only after a later LR update to the interpretation. The measured datum remains exact. Compare it to parameter-matched joint DeepSets/CNP, additive/no-interaction and basic sequential/GRU readers, all with the same carrier/private control; compare to full native replay/function grid and finite joint MHT at their real storage/compute. Conditional functions, group actions, source persistence, Bayes reweighting and replay are established ideas; originality requires a new measured quality/cost behavior, not renaming them.

The next generative branch must not be permanently restricted to `H_common`'s near row projector. B5's H is intentionally fixed, but `P_near r P_near^T` deletes prior-correlated near-null detail before RGB output. An independent CPU audit on existing8val×7query found40.64% pooled active-crop far-null GT-error energy in that near-null component; replacing only P_near by the same spatial support materially changes a one-pass GT-direction diagnostic. This is neither an inference result nor an optimized oracle bound.

Therefore compare a **far-null + operational spatial-support** residual and/or a soft all-observation likelihood with the hard-band control. Permit cue-correlated high-frequency revision, then measure correctness directly. Do not hard-freeze arbitrary PCA directions and call that identity protection. Data consistency alone is insufficient when the historical warp is wrong: the root has already observed better LR fits with worse HR quality. Treat uncertainty in the observation interpretation as part of the learned task, and audit errors under the actual estimated operator separately from GT evaluation geometry.

## Fixed controls, queries and costs

Use actual frozen H3 DiT proposals and native E/D where the core claims a generative prior; retain VAE-only +sameDC and observed LR bridge +sameDC. Full official49sampling, sampling-inner DC and finalDC must be versioned, shared across controls and charged explicitly. Use the same actual source sample(s), random seed, guide token/call budget and prior carrier per method; each source's private identity target is its own X0, not a universal HR mean. Add recent/all-history robust inverse and nonlinear realD inverse under the same estimated correspondences; joint-set/CNP and ordinary learned pair-confidence are mandatory controls for the learned interaction.

Metrics at every predeclared write/latecue/return prefix: full and evidence-region PSNR/SSIM/LPIPS; truth HF error in current-near-null and past-supported bands; exact LR residual; error under estimated versus evaluation geometry; identity displacement from X0 **and** private GT/HF error; correct-history versus shuffle/drop sensitivity; selected interpretation/calibration and corrections induced by the late cue. A private query is an operational region, not proof of semantic independence. Distortion/perception/private-information tradeoffs remain separate. Stability via blur does not count as preserved useful detail.

For real streams, use LR-only reidentification and confidence. Report uncovered returns/abstention as failures or reduced coverage rather than silently switching to oracle IDs. Current-frame HR metrics are independent of the model's estimated warp; GT-based flow/masks, if used for analysis, remain evaluation-only. Previously stored canonical queries after new evidence are secondary outputs with their own timestamps and update latency.

Record persistent state in bytes including all raw/full/proxy/archive/controller fields, scratch and model weights; per-event E/D/DiT/NN/controller/DC calls; fixed inference wait and any optional posterior refinement. Evaluate sourcewise and average queries within source first. Freeze actual train budget only after the causal payload, nonzero intervention path and shared0-correction baseline are verified; then complete the whole budget whenever finite, even if raw headroom is weak. No optimizer/gain/coordinate sweep is proposed by this draft.
