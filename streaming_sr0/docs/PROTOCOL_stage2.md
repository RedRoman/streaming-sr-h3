# Stage 2 协议：把块间不一致量化，并建立因果流式基线

日期：2026-10-17。本文件在任何 Stage 2 输出产生之前写定；之后只追加。

## 背景

Stage 1 证明训练能把 H3 的复原能力提上来（细节能量 0.30→0.83）。但那是**单块**评测：每个块独立采样，块与块之间没有关系。真正的流式要连续处理整段视频，此时块边界会暴露两个问题：
- 同一帧被相邻两块各生成一次，结果不同（第 0 步在冻结模型上测到 35% 的相对差异）；
- H3 的 DiT 是双向的（attention `mask=None`），块内每帧都能看到块内的未来帧，所以"块长"就是等待时间下界。

Stage 2 先把这两点量化，作为后续因果化和锚定的基线。本阶段**不训练**。

## 数据

VIDGEN 493 条中按 `code/pick_vidgen.py` 同一规则（仅用元数据）扩选 12 条，与 Stage 1 已用的 16 条不重叠，记为 stage2 集合。每条取连续 **124 帧**（整段），不是单块。
HR = 原生 1344×768 居中裁 832×480，不缩放；LR = 与训练一致的片段级退化，整段用同一组参数。

## 流式分块协议

块 k 覆盖帧 [17k, 17k+22)，新输出为 [17k+5, 17k+22)（块 0 输出全部 22 帧），重叠 5 帧。124 帧共 7 块（k=0..6），覆盖到第 123 帧。

两种运行方式：
- `indep`：每块独立采样，块之间无任何信息传递（Stage 1 的方式，现状基线）；
- `carry`：块 k>0 的重叠 5 帧，其 guide 像素改用块 k−1 已输出的高清结果（而非 U(LR)），其余不变。这是"把上一块结果接续给下一块"的最简实现，OmniVR 和 ReCaVSR 都有同类做法，**本阶段作为基线而非创新**。

两种方式都用 Stage 1 的 LoRA + innerDC，seed 101，其余设定与 Stage 1 完全相同。

## 指标

1. **块边界不一致（主指标）**：对每个块边界 k，重叠帧 f ∈ [17k+5, 17k+22) ∩ [17(k+1), 17(k+1)+5)，即 f ∈ [17k+17, 17k+22)。这些帧既是块 k 的新输出，也出现在块 k+1 的上下文里。比较两块对同一帧的生成频带：
   `BD = ‖N(Y_k(f)) − N(Y_{k+1}(f))‖² / ‖N(Y_k(f))‖²`，在整帧上计算。
   同时报同一块内相邻帧的 `N` 差（块内变化）作为尺度参照。
2. **跨块时序**：整段相邻帧的 `‖N(Y_t) − N(Y_{t+1})‖² / ‖N(G_t) − N(G_{t+1})‖²`，分别统计"块边界处的相邻帧对"和"块内部的相邻帧对"，两者之比是闪烁的直接证据。
3. **画质**：整段逐帧 PSNR / LPIPS / 能量比 / 余弦（与 Stage 1 同口径）。
4. **时延与吞吐**：每块的等待帧数（块长减重叠）、采样耗时、VAE 编解码耗时，分别记录；报端到端每块耗时与实时比。

先片段内平均，再片段等权平均；配对差给 bootstrap 95% 置信区间（10000 次，种子 0）。

## 判读（预先写定）

- 若 `indep` 的块边界不一致显著高于块内变化（比值 ≥ 2 且区间不跨 1），确认块间不一致是真实问题，Stage 3 的锚定设计有对象。
- 若 `carry` 相对 `indep` 把块边界不一致降低且不损失画质（LPIPS 不升、区间不跨 0），则它是一个有效基线，Stage 3 必须胜过它才算有贡献。
- 若 `carry` 降低了不一致但画质变差（LPIPS 升），说明简单接续会累积误差——这正是 OmniVR 承认的问题，记录下来作为 Stage 3 的动机。

## 已知局限

- H3 的 DiT 仍是双向的，本阶段不改注意力，所以"流式"仅指按块因果处理，块内仍是双向。真正的因果化在 Stage 3。
- 12 条片段规模小，只用于建立基线量级，不作显著性之外的推广。
- 评测素材是生成视频，真实视频的块间行为需另测。
