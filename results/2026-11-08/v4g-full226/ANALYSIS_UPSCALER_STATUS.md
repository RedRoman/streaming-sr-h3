# 分析：单就 upscaler 本身，是否已是正式管线中已确定的可交付流式因果 upsampler

日期：2026-11-08。本文只做判断与证据分层，不新增实验。所有实测数字来自本目录的 `receipts/`，未验证的部分明确标注。

## 一、结论分成两层，不能混成一句

如果问的是「这个 upscaler 模块本身，因果性与流式等价是否成立」，答案是**是，这一层已经确定**。如果问的是「它是不是正式生成管线里已经定下来、可以交付的组件」，答案是**还不是**。这两个答案不矛盾，因为问的是两件事：前者是模块的函数性质，后者是模块在系统中的集成、效用与契约状态。之前报告里「仍不是已确定的可交付流式因果 upsampler」是就整个系统与交付层面下的结论；在只问模块的口径下，机制这一层应修正为「是」。

## 二、为什么机制这一层可以判定为「是」

本轮把此前最大的机制缺口补掉了：输入不再是 37 帧真实加反转 30 帧合成的 67 latent，而是真实 345 帧源里取连续 226 帧、经 VAE 编码得到的 67 latent（源帧逐帧 SHA256 全不互同、回文匹配 0 次），六门在全长度上重跑，`all_passed = True`，阈值 0.01。

- 未来依赖：66 个未来切点全部精确 `0.0`；尾部替换 shared 20 帧，native 与 stream 均为 `0.0`。
- 前缀一致性最坏 `0.0010257959365844727`（k=21），属 bf16 数值级，不是未来信息泄漏；完整 67 帧 rerun 与 37-of-67 前缀均为 `0.0`。
- 流式前向与整段前向：max_abs `0.0006000250577926636`、mean_abs `2.7877129468834028e-05`，远低于阈值。
- 状态是有界的：62 个缓存卷积、最大时间长度 4、缓存 1756385280 B，不随序列长度增长；reset 清缓存、签名不符抛异常、reset 后帧数归零三项都成立。
- teacher 权重先存指纹、跑完全部前向再恢复核验（`True`），对照基线未被污染。

这些合起来足以判定：它是一个实现正确、不依赖未来输入、状态有界、可按 chunk 流式调用且流结果与全序列前向一致的因果上采样算子。**确定的是机制，不是收益，也不是系统身份。**

## 三、为什么「正式管线中已确定的可交付组件」仍然不是

差的三条都落在「正式管线中」和「可交付」这两个词上，与因果性无关。

第一，**没有在线集成联调**。本轮是独立评测包离线加载整段已编码 latent 调用的（`offline batch whole-VAE encode/decode; NOT real-time throughput`），不是自强迫 DMD 生成链里边产 latent、边上采样、边解码的在线逐段链路。「正式管线中」这个定语尚未成立：冻结审阅包的 PLAN 仍是 BASELINE MODE ONLY，A/B 双臂未授权启动，项目还没进入选定版本并集成的阶段。整段 VAE 的在线因果性、端到端延迟与吞吐都未测量。

第二，**效用未确定**。主指标 `0.06744341552257538` 只是 v4g 相对原始双向 teacher 的 latent MSE，teacher 不是 GT；它衡量「和老办法差多少」，不是「比老办法好多少」。像素诊断口径下 teacher 对 VAE 重建参考的 mean MAE `4.514606004845476` 反而低于 v4g 的 `5.350527158904099`，这个口径不是 GT、只能作边界提示，但足以说明**没有留出评测证明收益**，也没有新 best 模型；td_m 分母未修。没有匹配强对照的留出评测，就不能说「该选它」。

第三，**交付契约未定义**。逐 chunk 在线调用约定、与 VAE 的时间对齐（VAE 逐点时间映射未验证，误差面板时间轴只是 67→226 的显示重采样）、reset 与错误恢复时机、延迟 / 吞吐预算、以及 1756385280 B 常驻缓存的部署成本都未形成约定。本轮 1654.205 秒是离线批处理耗时，不是端到端速度。没有契约，就没法把模块「交出去」给集成方直接用。

还有一条贯穿性的边界：本轮 LR 是 HR 的 area 下采样合成退化，没有真实 LR/HR 配对 GT，不给 PSNR / SSIM；视频只做 ffprobe 与全帧解码逐帧计数验收，**未做人工实际检视，不声称看过视频**。

## 四、直白版

把它想成流水线上的一个工人：我们让他单独干了一整天真实的活，确认他不会偷看后面才送来的料，一件一件递给他和一次性把全部料堆给他，做出来的东西一样，而且桌上不会越攒越多东西。就这个工人本身，合格了，不用再怀疑。但「他已经是这条线上定下来的正式工人了吗」，还不是，因为整条线从上游产料、他加工、下游出图三截串起来不停转，从来没一起跑过；没有一次像样的比试说明他比原来那个老工人干得更好，测出来的只是他和老工人差多少；也没人写清楚别人该怎么把料递给他、一次递几件、他记的东西什么时候清空、出错了怎么办、允许多慢多占地方。

所以最直白的两句话：问「这个模块本身是不是不偷看未来、能不能一段一段跑」，**是，已经定死，不用再测**；问「正式系统里是不是已经定用它、能交付了」，**还不是**。

## 五、要把「还不是」变成「是」，需要做什么

不是再单独跑一遍 A–F。需要三件独立的事：把它接进正式生成链做在线逐段联调并测端到端延迟 / 吞吐；补一次匹配强对照的留出效用评测，明确它相对原始双向 teacher 在完整生成质量上是否带来收益（保留负结果）；把接口、时间对齐、reset / 错误恢复、延迟与显存预算写成契约。在此之前，A/B 训练双臂、版本选定、以及把模块写进论文 / 交付说明中的「已确定」表述都应当保留边界。上述三件在本轮**均未启动**。
