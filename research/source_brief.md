# 先看结论

**流式 SR 值得继续挖，最吸引我的主线是：把低清视频流逐步变成一份持续更新的高清场景。** 一处织物、雕刻或人物衣服上的纹理，被看见、遮挡、再看见时，能作为同一份细节被取用；新的视角又可以让这份细节变得更准确。它的展示语言很直接：镜头走一圈回来、物体转身、直播画面不断拉近拉远。

本月新作已提供可复用的一步生成、参考传播和流式执行底座。研究可以把更多精力放在“高频细节以什么状态存在、怎样随观测更新、怎样被连续读出”上。这是本轮从论文归纳出的研究判断。

先打开 [FastVR 官方长视频对比](https://chenxx89.github.io/projects/fastvr/) 看实际增强效果，再读 [RelayVSR](https://arxiv.org/abs/2609.37850) 和 [ReCaVSR](https://arxiv.org/abs/2609.37831) 的状态接口。FastVR 页面提供真实视频与生成视频的同步输入／输出比较，适合建立第一轮视觉预期。

# 路线一 持续更新的高清细节状态

## 想做出的三个展示

1. **绕一圈还是同一件衣服。** 人物穿刺绣外套转身，纹理离开视野数秒后重新出现；局部花纹不重新随机生成。

2. **新观察真的让画面更清楚。** 镜头由远到近看雕刻，再拉远；新近景提供的信息进入同一个状态，随后远景输出保留被确认的结构。

3. **细节稳定，光照仍然变化。** 金属器物转动时，雕刻保留身份，高光仍随视角移动。用于展示状态中的持续纹理与瞬时外观可以共同工作。

三项都是拟研究能力，不是上述论文已经验证的结果。视觉主张是“同一份细节不断被理解和更新”，第一轮不要求重建完整三维世界。

## 最小模型接口

输入为已到达的低清帧或块 yₖ，内部维护短期运动状态 Sₖ，以及跨块可检索的细节状态 Mₖ。当前输出由观察、状态检索结果和生成先验共同得到：

```text
fₖ = observation_encoder(yₖ)
rₖ = read(Mₖ₋₁, current_correspondence)
detailₖ = detail_generator(fₖ, rₖ, Sₖ₋₁)
x̂ₖ = renderer(fₖ, detailₖ)
Mₖ = update(Mₖ₋₁, observed_features=fₖ,
            proposed_detail=detailₖ, correspondence)
```

每个状态条目先用局部 patch 表示，保存内容描述子、局部坐标、可对齐的多尺度细节、观测支持信息和最后更新时间。短期连续运动用光流关联，长间隔返回用内容检索重新定位；早期原型可人工确认目标区域，以便先判断细节状态的价值。再逐步换成自动关联。

状态更新同时做两件事：积累新观察能解释的结构，保留当前观察尚不能决定的细节解释。这里的生成细节是模型的选择，不当作新的真实观测反复累加。新视角出现后，更新应发生在同一局部内容上；第一次已经显示的历史帧不回写，后续输出使用更新后的状态。

最小机制实验甚至可以先不学习更新器。用局部规范纹理 T 和已知的变换／模糊／下采样算子 Aᵢ，把已到达观测写成一个小型求解问题：

```text
T_new = argmin_T Σᵢ ||Aᵢ(T) - yᵢ||²
                + λ ||P_unobserved(T - T_old)||²
```

第一项让状态解释实际观察，第二项保持目前没有新信息约束的细节。先在已知退化与映射的数据上，用算子可辨识性构造近似 P_unobserved，做少量迭代；随后用小网络摊销更新。其作用是给出可分析的能力原型，真实视频中的对应、退化和可辨信息估计再逐步学习。

一个可做的实现是冻结 RelayVSR 的生成器和小解码器，将局部状态渲染为当前姿态下的参考，编码后通过参考分支注入。先做外部参考拼接／替换基线，再训练轻量映射 adapter 适配参考分布。如果采用 FastVR，则增加单独的状态读取条件分支，保留原有块处理流程，避免第一步同时修改底座和时序协议。这些接口适配仍需实际验证，不假设官方模型原生支持任意状态注入。

## 数据与训练

首轮准备三组 10–30 秒的高质量短片：持续可见的精细纹理、转身／遮挡再现、远近尺度变化。由完整高清原片构造一致的低清流，保留原片作评估目标；另外录制真实压缩视频作展示。主体优先选衣服、编织物、雕塑、建筑表面和玩具，便于判断局部结构是否相同。

训练按时间前缀展开。读到第 k 块时，状态更新只使用已经到达的 LR 内容；高清真值只作训练监督。先训练状态读出 adapter，再在较短 rollout 中训练更新器，最后增加遮挡间隔和回访跨度。每次 rollout 保持同一份生成细节选择，学习何时延续、何时随新信息调整。

目标包括当前画质、可对应区域的纹理保持，以及新信息出现后的重建改善。不同光照下的高光不直接逐像素锁定；这部分通过当前外观分支处理。第一阶段可在合成形变和已知对应中学习，再迁移到真实视频匹配。

## 第一轮最有判断力的实验

同一条输入流分别使用：原始底座、延长 KV 的等预算基线、固定高清关键帧参考、按新观测更新的细节状态。所有方法具有相同的输入前缀和等待预算。

展示四列同步放大视频：首次出现、离开前、再出现、获得新近景后的输出。既比较回访时的纹理身份，也比较获得额外信息后的准确度；只让纹理固定不变不能同时完成这两个目标。搭配对齐后的局部重建误差、感知距离、回访一致性、状态占用与额外处理时间。

这里已有重要前作：[Long-Term Self-Exemplars](https://cqf.io/papers/Video_Super-resolution_ICRA2023.pdf) 已利用远隔帧和跨尺度同实例纹理；RelayVSR 已有参考／滚动双记忆；[InfVSR](https://arxiv.org/abs/2510.00948) 已研究长视频生成超分一致性。本路线进一步检验的是：**可定位的生成细节，能否在长流中持续存在，并随观测改变同一份解释。** 机制应由上述联合实验说明。

## 两周原型

第 1–3 天复现一个公开底座并固定数据和输入预算；第 4–6 天搭建局部 patch 状态、对应和固定参考版本；第 7–10 天加入新观测更新与轻量参考 adapter；第 11–14 天完成回访、尺度变化和外观变化三组视频面板。两周交付是机制原型和对比结果，不以复现全部论文训练为前提。

进入第 3–6 周后，扩大对象和运动种类，减少人工关联，增加更长间隔、多对象与切镜头后的重新检索。只有“维持身份”和“利用新观察改善细节”同时成立，才值得扩大底座训练。

# 路线二 可连续放大的高清视频流

## 视觉目标与核心问题

直播画面中把放大框移到鹦鹉羽毛、衣服刺绣或建筑窗格，连续改变倍率；退出放大再回来，仍然看到相容的细节。它可以做成双窗口：左侧全景持续播放，右侧任意区域的高清观察窗。

**研究问题是：时间更新和空间查询能否共享同一份细节状态。** FastVR 已支持任意尺度；窗口外的 [AVSR-Diff，2026-07-01](https://arxiv.org/abs/2607.00987) 已将生成先验与连续解码分开。后者包含双向采样和解码传播，本轮要研究持续到来的观测，以及倍率和区域在播放中不断变化时的统一读出。

## 可执行建模

在路线一状态上定义查询 q=(ROI, scale, pixel_footprint)。观察到达才更新状态，改变放大倍率只发起读取。先使用共享细节金字塔提供 2×、4×、8× 三层，再替换成带像素覆盖范围的连续解码器；跨尺度读取采用抗混叠聚合。

训练同一时间点的多组 ROI 与尺度查询。高倍率结果降采样后应与低倍率查询相容；同时保留高清监督，避免通过全部变模糊满足一致性。时间上增加“放大—移开—返回”的查询轨迹，让模型学习访问顺序不应改变已经建立的场景内容。所有读请求保持状态只读，排除界面查询顺序本身造成的纹理改变。

已有 [FOCAS](https://github.com/UMass-LIDS/focas) 和 [CRFP](https://arxiv.org/abs/2212.13525) 涉及注视区域计算和高分区域传播。因此本路线的重心是时间与尺度下的细节身份、更新和读出；ROI 计算节省是实现手段。

## 两周能做什么

先用固定尺度底座跑一个全景流，加上保留状态的多层局部细节读取。测试连续倍率循环、快速移动 ROI、返回旧区域、物体转动四类操作。第一周做无训练共享金字塔基线，第二周训练小解码头，在相同显示分辨率和像素预算下比较“每次独立 SR”和“共享状态查询”。

可见成功是：放大时出现丰富细节，缩回时结构不跳，移开再回来仍保持身份。4–6 周再做连续倍率和稀疏按需细节生成。8× 是探索目标，首轮优先确认 2×–4× 的效果与成本。

# 路线三 流式时空超分

## 视觉目标与时间定义

让低清低帧率视频中的裙摆、羽毛、头发和水滴，输出为同时更清晰、更顺滑的短片。相比只看静态 crop，这条路线用运动过程展示恢复能力。

第一版采用固定的一帧输入等待：当下一帧到达后，生成前一时间区间的高清中间帧。这样明确是在有限等待下插值。若以后希望零等待生成未来时刻，那属于外推，需要单独建模与评价，不能把两种设置混报。

## 技术切入

状态分成持续纹理与短时运动两部分，读出接口接收空间尺度和区间内时间。持续部分负责同一根羽毛／同一块布料的细节身份，短时部分提供形变、可见性和瞬时外观。先用现成在线 SR 与插帧串联作强基线，再让两者共享对齐后的高频特征，联合生成中间时刻的细节。

使用高帧率高清视频构造空间降采样和时间抽帧，记录真实曝光，先从空间 4×、时间 2× 的统一协议做起。监督输出帧的细节与运动对应；避免简单要求相邻高频内容恒定，否则会把动态纹理和高光冻结。

窗口外 [OSDEnhancer，2026-01-28](https://arxiv.org/abs/2601.20308) 已有一步生成式时空超分及双向解码器；[GS-STVSR，2026-04-20](https://arxiv.org/abs/2604.18047) 已支持连续时空查询。这里要比较的是有限等待下，持续细节与瞬时运动共同读出是否优于“先 SR 再插帧”和“先插帧再 SR”。

## 两周能做什么

第 1 周建立上述两种串联基线，并用相同缓冲延迟输出；第 2 周只训练共享特征的轻量时空读出头，选择舞蹈衣物、飞鸟、流水三个素材组做 5–10 秒对比。先展示细节随运动的演化，再决定是否训练生成式时空 adapter。

首轮统计输出内容帧率和实际处理吞吐分别是多少。生成 60 FPS 视频不代表系统每秒能处理 60 帧。4–6 周扩展到更长流和不同等待预算，以画质、时间连续性和延迟三者的变化决定投入。

# 第一周的具体落点

**先做路线一，使用 FastVR 建视觉基线，用 RelayVSR 研究参考读出接口。** 首轮只需十余条有清楚细节与回访的片段，每条提供一张固定位置 crop 和整段同步视频；先把“我们想看到的变化”呈现出来，再决定扩大模型。

| 产物 | 内容 |
| - | - |
| 统一播放面板 | LR、底座、固定参考、更新状态四路同步，显示输入时间和输出时间 |
| 三类素材 | 同一表面重现、远近变化、纹理保持但光照变化 |
| 简单状态可视化 | 当前检索到了哪一处历史内容，新观察更新了哪里 |
| 一张结果图 | 回访一致性与新信息带来的准确度改善，分别报告，附额外延迟 |

工程规划暂按一名熟悉 PyTorch 的研究者、一张 48–80GB GPU 做公开模型复现和小 adapter 实验；这是资源假设。24GB 设备先降低分辨率或只跑 patch 原型。公开推理峰值显存不能直接用作训练预算，第一天需实际 profiling；本次没有下载权重或运行训练。

本轮补查也确认，Kaiming He 的最近一个月未发现新的图像／视频生成 backbone 或范式论文；10 月 1 日上传的 VISTA 属于视觉记忆与交互推理，早期内容已公开。流式 SR 当前更直接的机会来自上述新作及生成状态的组织方式。[Kaiming 官方论文列表](https://people.csail.mit.edu/kaiming/publications.html) · [VISTA](https://arxiv.org/abs/2610.02200)
