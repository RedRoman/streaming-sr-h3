## 判读（按预注册规则）

阈值是目标框 PSNR ≥ +0.3 dB 或 LPIPS ≤ −0.02 且区间不跨 0。上界的 PSNR 为 +0.088（区间跨 0），LPIPS 为 −0.0155（未达 −0.02）。**两项都不满足，判为 guide 通道在冻结 H3 下不能承载记忆细节，该路线停止。**

两个附带结论：
1. **内容确实起作用**：真实记忆优于同位置同能量的无关内容（+0.27 dB，记忆区域 +0.69 dB，区间不跨 0），写错内容还会变差。所以不是"模型无视 guide"，而是收益太小。
2. **H3 在记忆利用上不如经典方法**：同样的 guide，经典投影比 H3 高 2.55 dB，H3 只在 LPIPS 上好 0.022。这直接影响"用 H3 做记忆"的新颖性论证。

## 为什么上界这么低

记忆掩码平均只覆盖目标框的 10%（带门控时 4.7%）。原因是回访时目标姿态变了，DIS 光流的前后向一致性只有 2%–3%（相邻帧是 63%–100%，见 `code/reg_sanity.py`）。32 个事件里只有 bottle-14（0.90）、crab-12（0.79）、monkey-11（0.33）、robot-13（0.22）有像样的覆盖。即使上界成立，收益也只会集中在少数姿态变化小的事件上。

## 未完成的部分

带门控的 `mem_gt_oflow` 只跑了 2/32 个事件就停止了。理由：它的覆盖率（4.7%）严格低于无门控版本（10%），写入的记忆更少，上界只会更弱；更有利的无门控版本已经不通过。已完成的 2 个事件也显示 −0.41 dB。`mem_gt_lrflow` 和 `mem_self_lrflow`（可部署变体）同理未跑，因为它们的上限不会超过 oracle 版本。
