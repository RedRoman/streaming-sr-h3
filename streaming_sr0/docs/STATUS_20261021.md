## 四、两个跨块机制：均失败

真实素材上零空间跨块仍有 0.487 相关，据此预期跨块机制应当有用。**实测相反。**

| | 边界 flicker | 块内 flicker | 边界−块内 |
|---|---:|---:|---:|
| 基线（逐块独立） | 25.18 | 4.42 | +20.76 |
| 绝对索引噪声 | 40.54 | 4.22 | +36.32 |
| 跨块 KV 缓存 | **47.16** | 5.03 | +42.13 |

块内基本不动，**边界分别恶化到 1.6 倍和 1.9 倍**。

**推理错在哪**：「信号相关」不等于「模型能利用它」。0.487 说明 GT 的细节跨块持续，但没说明把上一块的**模型输出**（与 GT 余弦仅 0.434，一半以上方向错误）喂给下一块会有帮助——实际是把错误细节一并传递，并在边界造成更强不一致。

这与 Stage 5 在生成素材上的结论方向一致，但当时给出的理由（"没东西可搬"）是错的。真正的理由是：**模型自生成的细节质量不足，不值得跨块传递。**

## 五、`R_φ` 范围支路：七次失败后的定论

模块本身有效：realistic 退化上 LR 域稳定 **+1.95 ~ +2.01 dB**。失败的是**路由**——无法判断「这个观测是否已经干净」，于是对近乎完美的输入（`pillow_bicubic`，基线 58 dB）也施加修正。

| 方案 | 有机制 | 损失在乎 | realistic | bicubic |
|---|:-:|:-:|---:|---:|
| 原始 L1 | ✗ | ✗ | +1.95 | −14.17 |
| 按样本归一化 | ✗ | ✓ | ~0 | ~0（塌成恒等） |
| 铰链守护 λ=10 | ✗ | ✓ | ~0 | ~0（塌成恒等） |
| 逐帧时序描述子 | 弱 | ✗ | +2.01 | −8.11 |
| 门控 + L1 | ✓ | ✗ | +1.64 | −11.50 |
| 门控 + 相对损失 | ✓ | ✓ | ~0 | ~0（塌成恒等） |
| 门控直接监督 | ✓ | ✓ | +1.98 | −22.27 |

**根因已测明**：门控的标签完美（`want` 0.02 vs 0.90，差 45 倍），但**输入里没有能预测它的信息**——六维证据的类间分离度全部无效，且真实素材上方向相对生成素材翻转（真实素材自带传感器噪声，`pillow_bicubic` 的时序抖动反而大于 `realistic`）。

**结论**：盲判"要不要修"在真实素材上缺可用信号。不再调第八个损失，按「只在 realistic 启用」交付（评测集 19/24 为 realistic）。

## 九、后续决策

### 「超分做完」的定义

一个**端到端锁定的配置**，在同一批 24 条真实素材上同时给出：PSNR、LPIPS、时序指标（flicker / warp err）、每秒输出时延、峰值显存。FlashVSR 与 InfVSR 用同一批片段、同一套指标跑出对照。

### 执行顺序

1. **运行 `rphi` 臂** — perc LoRA + `R_φ` 估计的 guide。这是产品形态，决定可部署配置的真实水平。
2. **把 Turbo 放进评测配置** — 测其画质代价与吞吐收益，而非在合成输入上单报。
3. **明确因果化取舍** — 当前评测不是真流式，须改掉或在报告中讲明。
4. **搭建 FlashVSR / InfVSR 推理栈** — 同口径对比。
5. 其后转 Stage 8（omni），数据与协议已就绪。

### 暂缓
